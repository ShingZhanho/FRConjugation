# v5.2.0

Guess APIs now choose between catalogue lookup and inference by infinitive membership, across Swift, C/C++, Kotlin, C#, Python, and TypeScript/JavaScript.

- Known infinitives return only catalogue results, preserving missing forms and unsupported voices, moods, tenses, and persons.
- Unknown infinitives continue to use raw inference.
- The same rule applies to single forms, collections, participles, gérondifs, common prefixes, and asynchronous APIs.
- Catalogue lookup and raw inference APIs are unchanged. The bundled catalogue is unchanged.

## Behavioral compatibility

This is an intentional behavioral breaking change released as 5.2.0. Signatures remain unchanged, but callers may now receive null/nil, empty collections, or fewer entries where guessing previously generated forms absent from a known verb's catalogue entry. For example, guessing first-person singular present `falloir` now returns no form. Guessing the present participle or gérondif of `entre-nuire` preserves the catalogue omission. The guessed common prefix of `manger` is now `mang`, matching catalogue lookup.

Use the raw-inference APIs explicitly if hypothetical forms for known verbs are needed. Membership follows existing catalogue lookup semantics: NFC-equivalent spelling is accepted, but case and surrounding whitespace are preserved. Only the inference path trims and lowercases input. Homonym selection still follows the existing catalogue rules; a missing requested homonym of a known infinitive does not trigger inference.

All language conformance suites pass with updated shared fixtures for defective verbs and retained unknown-verb predictions.
